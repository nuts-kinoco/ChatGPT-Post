## 0. 評価基準

- **発生確率**: L（低）/ M（中）/ H（高）
- **影響**: L / M / H / **C**（Critical: データ損失、アカウント喪失、二重送信、失敗の成功誤報）
- **重要度** = 確率 × 影響の総合判断（Critical / High / Medium / Low）
- **扱い**: Mitigate（緩和）/ Accept（受容・明記）/ Avoid（回避）/ Transfer（PO 判断へ）

## 1. リスク一覧

### R-001 規約・アカウントリスク（削除禁止）

| 項目 | 内容 |
|---|---|
| 分類 | 法務・アカウント |
| 内容 | OpenAI 利用規約は Output の自動・プログラム的な抽出、レート制限・保護措置の迂回等を禁止している（PO 調査 2026-09-14。Claude の自動再確認は 403 で不可、OQ-001）。本プロダクトは通常 UI を自動操作して回答を取得するため、規約違反と判断されアカウント警告・停止に至る可能性がある |
| 確率 / 影響 | M / C |
| 重要度 | **Critical** |
| 扱い | **Accept + Mitigate + Transfer（最終判断は PO）** |
| 緩和策 | (1) 個人のローカル・低頻度・直列利用に限定（CON-006）。(2) CAPTCHA・チャレンジ・認証・レート制限を一切回避しない（CON-011, SEC-008）。(3) stealth / UA 偽装 / fingerprint 偽装をしない（SEC-008）。(4) 内部 API・Cookie・HAR を扱わない（CON-008, SEC-002, SEC-003）。(5) 自動再送・自動待機再試行をしない（FR-038, FR-042）。(6) README とリスク登録簿に明記し、法的評価を断定しない（SEC-009） |
| 残存リスク | 緩和後も **残る**。「規約上問題ない」とは表現しない |
| 監視 | アカウント警告・異常なチャレンジ頻度の増加を PO が観察。発生時は利用停止を検討 |

### R-002 ChatGPT UI（DOM）の変更でブリッジが壊れる

| 項目 | 内容 |
|---|---|
| 分類 | 保守性 |
| 内容 | ChatGPT は SPA で頻繁に UI を更新する。入力欄・送信ボタン・モデル選択・assistant メッセージ・生成中表示のいずれかの構造変化で操作不能になる |
| 確率 / 影響 | H / M |
| 重要度 | High |
| 扱い | Mitigate |
| 緩和策 | (1) アクセシビリティ優先の selector（NFR-005）。(2) selector を一か所に集約し用途・代替・確認条件を持たせる（FR-022, NFR-005）。(3) 確認できなければ誤操作せず `DOM_CHANGED` で停止（FR-041）。(4) `inspect-ui` で差分診断（FR-004）。(5) sanitized fixture による回帰テスト（NFR-008）。(6) UI 変更時の修正ガイドを Phase 7 で作成 |
| 残存リスク | 変更のたびに人手修正が必要。許容する |

### R-003 二重送信

| 項目 | 内容 |
|---|---|
| 分類 | 正確性・アカウント |
| 内容 | タイムアウトやクラッシュ後に「送信されていない」と誤判断して再送すると、同一質問が 2 回送られ、利用枠を消費し、回答の対応付けも壊れる |
| 確率 / 影響 | M / C |
| 重要度 | **Critical** |
| 扱い | Avoid |
| 緩和策 | (1) 送信は 1 リクエスト 1 回（FR-025）。(2) 送信直前の write-ahead マーカーと状態記録（FR-025, ADR-005）。次回起動時にマーカーのみが残っていれば `SUBMIT_STATE_UNKNOWN` で停止（FR-014）。(3) 送信後不明状態からの自動再送禁止（FR-038）。(4) process ロック + requestId でグローバルな `submit.marker` / `result.json` の存在判定（FR-035, FR-036, A-031）。(5) 処理済み requestId の冪等拒否（FR-014、Must）。(6) Live テストで requestId をプロンプトに埋め込み回答を照合（FR-030）。すべて Must 要件 |
| 残存リスク | ユーザー（呼び出し元）が新しい requestId で意図的に再送することは可能。それは仕様。OS クラッシュで marker の fsync が完了しない極小の窓は残る（tmp → fsync → rename で最小化） |

### R-004 生成完了の早期誤検出 / 永久待機

| 項目 | 内容 |
|---|---|
| 分類 | 正確性 |
| 内容 | 思考中（reasoning）フェーズ、ストリーミング一時停止、ツール呼び出し表示等により「完了」と誤検出して途中の回答を保存する。逆に生成中 UI を見失って `timeoutMs` まで待つ |
| 確率 / 影響 | M / H |
| 重要度 | High |
| 扱い | Mitigate |
| 緩和策 | (1) 多信号の完了判定（FR-026）。(2) 生成中 UI 未観測時の代替経路と「不明なら成功にしない」（FR-027）。(3) 安定化ウィンドウ（DOM 一定期間不変）。(4) 長時間生成の Live シナリオ（AC-019, LS-06）。(5) pro 等の長考 preset を含めた Live 検証 |
| 残存リスク | ChatGPT が回答を途中で編集・差し替える UI 挙動があれば誤検出し得る。出力上限の打ち切り（「続きを生成」）と複数回答（A/B）は fail closed（`CHAT_ERROR`）で扱う。Phase 5 で fixture を追加 |

### R-005 モデル / effort の誤選択・暗黙フォールバック

| 項目 | 内容 |
|---|---|
| 分類 | 品質 |
| 内容 | 要求 preset が UI に存在しない、名称が変わった、選択がリセットされた、利用上限で自動的に別モデルへ切り替わった、等により意図しないモデルで回答が生成される |
| 確率 / 影響 | M / H |
| 重要度 | High |
| 扱い | Avoid（fail closed） |
| 緩和策 | (1) 選択後に UI 表示を読み取り一致確認（FR-021）。(2) 不一致・不明は送信せず失敗（CON-007）。(3) `observedPreset` を result.json に記録（FR-010）。(4) preset 名称対応表を一元管理（FR-022） |
| 残存リスク | ChatGPT が「表示は pro、実行は別モデル」のように内部で切り替えた場合は検出不能。内部 API を見ないため受容 |

### R-006 認証切れ・CAPTCHA・Cloudflare チャレンジ

| 項目 | 内容 |
|---|---|
| 分類 | 可用性 |
| 内容 | セッション失効や bot 判定により、ログイン画面やチャレンジ画面が出る |
| 確率 / 影響 | M / M |
| 重要度 | Medium |
| 扱い | Mitigate（手動介入） |
| 緩和策 | (1) 検出して `manual_intervention_required` で停止、スクリーンショット保存（FR-017）。(2) `doctor` でログイン状態を事前診断（FR-002）。(3) 可視ブラウザなので PO がそのまま操作可能（CON-005）。(4) 突破・回避は禁止（SEC-008） |
| 残存リスク | 頻発する場合は R-001 の兆候として PO が判断 |

### R-007 プロファイル競合・ロック不備

| 項目 | 内容 |
|---|---|
| 分類 | 正確性・安定性 |
| 内容 | 同じ専用プロファイルを 2 プロセスが開く、クラッシュで stale lock が残り永久に `ALREADY_RUNNING` になる、Windows のファイルロックで削除できない |
| 確率 / 影響 | M / M |
| 重要度 | Medium |
| 扱い | Mitigate |
| 緩和策 | (1) process ロック + グローバル marker（FR-035, FR-036, ADR-005）。(2) stale lock は所有 PID の生存確認と起動時刻照合で判定し、内容照合付き rename で回収、所有トークンを送信直前に再検証（回収競合の窓が残っても送信しない）、不明なら `ALREADY_RUNNING` 側（FR-037）。(3) ブリッジ外プロセスによる占有は起動前プリチェックで `PROFILE_IN_USE`、起動例外は `BROWSER_LAUNCH_FAILED`、ブリッジ自身のロックは `ALREADY_RUNNING` と区別（FR-019）。(4) `doctor` がロック状態・占有プロセスを表示（FR-002）。(5) ブラウザ終了（上限付き）の後にロックを解放（FR-035）。(6) Windows の `lockfile` 排他オープンの挙動は Phase 4 Live で確認 |
| 残存リスク | WMI 照会が使えない環境では PID 再利用を検出できず `ALREADY_RUNNING` になる場合がある。`doctor` で表示し手動削除を案内。受容 |

### R-008 Markdown 抽出の欠落・破損

| 項目 | 内容 |
|---|---|
| 分類 | 品質 |
| 内容 | コードブロックの言語指定・表・数式・ネストしたリスト・日本語が DOM→Markdown 変換で崩れる。コピー操作が Markdown ではなくプレーンテキストを返す（OQ-003）。ページ内フックで捕捉したコピー内容が別メッセージのものである |
| 確率 / 影響 | M / M |
| 重要度 | Medium |
| 扱い | Mitigate |
| 緩和策 | (1) 多段抽出と品質記録（FR-031, FR-032）。(2) 捕捉したコピー内容を DOM の innerText と照合し、不一致なら DOM 経路へ（FR-031 (1)）。システムクリップボードは使わない（ADR-004）。(3) 要素種別ごとのテスト（FR-033）。(4) `extractionQuality: degraded` を呼び出し元に伝える。(5) クリップボード衝突は ADR-004 のページ内捕捉で解消（OQ-007 解決） |
| 残存リスク | DOM→Markdown 変換で ChatGPT 固有のレンダリング（数式・引用内コード等）が完全には再現されない場合がある。`degraded` として通知し受容。Canvas 等のサイドパネルに生成された本文は取得せず `EXTRACTION_FAILED(canvas)` |

### R-009 trace / screenshot / log による認証情報・個人情報の漏洩

| 項目 | 内容 |
|---|---|
| 分類 | セキュリティ |
| 内容 | Playwright trace はネットワークヘッダー・Cookie・画面を含み得る。スクリーンショットにはアカウント名・他の会話タイトルが写る。ログにプロンプト・回答本文が出る |
| 確率 / 影響 | M / H |
| 重要度 | High |
| 扱い | Mitigate |
| 緩和策 | (1) `runtime/` を gitignore（SEC-004）。(2) ログ redaction とそのテスト（SEC-005）。(3) README の注意書き（SEC-006）。(4) Cookie/Token をプログラムで取り出さない（SEC-002）。(5) trace は保存前にサニタイズ（`*.network` を削除、`resources/` は CSS / フォント / 画像の許可リストのみ残す、redact と同じ正規表現で残存検査）し、失敗時のみ保存（SEC-010, 15-SECURITY §3）。(7) `inspect-ui --dump-dom` の生 DOM は `runtime/` 配下にのみ書き、fixture 化はサニタイズスクリプト（秘密情報パターンでヒットすれば失敗）を通す。(6) `reviews/` に Codex へ渡す資料から runtime パスを含めない運用（Phase 3） |
| 残存リスク | スクリーンショットの画面内容（アカウント名等）は除外できない。trace をそのまま第三者へ共有した場合は防げない。運用で担保 |

### R-010 Windows 固有の問題

| 項目 | 内容 |
|---|---|
| 分類 | 互換性 |
| 内容 | パス区切り・長いパス・ファイルロック中の rename 失敗・PowerShell 5.1 の `&&` 非対応・コンソールの UTF-8 出力・クリップボード API の挙動・ブラウザ子プロセスの終了処理 |
| 確率 / 影響 | M / M |
| 重要度 | Medium |
| 扱い | Mitigate |
| 緩和策 | (1) Windows を第一対象として Live テストを Windows で行う（CON-013）。(2) アトミック rename は同一ボリューム内で行い、失敗時は `WRITE_FAILED`（FR-013）。(3) PowerShell wrapper は Phase 6 で 5.1 を確認、7 は OQ-008 の判断に従う |
| 残存リスク | 未検証の PowerShell 7 / 他ロケールでの挙動差。受容 |

### R-011 呼び出し元（Claude Code）が結果を誤読する

| 項目 | 内容 |
|---|---|
| 分類 | 統合 |
| 内容 | Claude Code が途中書き込みの result.json を読む、`status` を見ずに response.md を読む、古い response.md を新しい回答と誤認する |
| 確率 / 影響 | M / M |
| 重要度 | Medium |
| 扱い | Mitigate |
| 緩和策 | (1) アトミック書き出し（FR-013）。(2) requestId ごとのディレクトリ分離。(3) Phase 6 の wrapper が終了コードと `status` を伝播し、`completed` 以外では response.md を返さない |
| 残存リスク | 呼び出し元が wrapper を使わず直接ファイルを読む場合。利用手順で注意喚起し受容 |

### R-012 ChatGPT の利用上限（メッセージ数 / 時間あたり）

| 項目 | 内容 |
|---|---|
| 分類 | 可用性 |
| 内容 | pro 等の上位 preset は回数制限がある。到達すると UI が警告やモデル切替を行う |
| 確率 / 影響 | M / M |
| 重要度 | Medium |
| 扱い | Mitigate + Transfer |
| 緩和策 | (1) `RATE_LIMITED` は `manual_intervention_required` で停止し自動待機・再送しない（FR-029, FR-042）。(2) 送信前のモデル自動切替は FR-021 の一致確認で検出。(3) 上限管理は PO の判断（Transfer） |
| 残存リスク | 送信後・生成中に発生するモデル切替は検出対象外（FR-021、R-005 と同じ）。受容 |

### R-014 Codex レビューが実施できない

| 項目 | 内容 |
|---|---|
| 分類 | プロセス |
| 内容 | `codex exec` のフラグ変更、認証切れ、非 TTY 問題でレビューが動かない |
| 確率 / 影響 | L / L |
| 重要度 | Low |
| 扱い | Mitigate |
| 緩和策 | (1) 実行前に `codex --version` / `codex exec --help` を確認（2026-09-14 時点で `--ephemeral`, `-C`, `-m`, `-c`, `-o`, `-s read-only` を確認済み）。(2) 失敗時は証拠保存・自己レビュー代替・「外部レビュー未実施」明記（OPS-005） |
| 残存リスク | 自己レビューのみになる場合は独立性が下がる。報告に明記して受容 |

### R-015 Playwright / Chromium 側の変更

| 項目 | 内容 |
|---|---|
| 分類 | 依存 |
| 内容 | Playwright のメジャー更新で `launchPersistentContext` の挙動やクリップボード権限が変わる。Chrome のポリシー変更で永続プロファイル自体が制限される |
| 確率 / 影響 | L / M |
| 重要度 | Low |
| 扱い | Mitigate |
| 緩和策 | (1) Playwright のバージョンを固定（lockfile）。(2) `doctor` がバージョンを表示。(3) OQ-004 で Chromium / Chrome の選択を決める |
| 残存リスク | 上流の方針変更は制御不能。発生時は D-02 / D-03 の再考トリガー。受容 |
