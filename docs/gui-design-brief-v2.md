# [UI/UX Design Brief] ChatGPT Web Bridge 軽量管理GUI（管制塔）
## 0. 改訂メモ（壁打ち案からの変更点）
本ブリーフは壁打ちで出た初期案（`S:\design.md`）を、実装ロードマップ（[`docs/gui-app-roadmap.md`](gui-app-roadmap.md) の "Now" スコープ）に合わせて整理したものです。設計者はこのセッション（Claude）＋ユーザー、コーダは別途Codexへ依頼します。このデザイン依頼はビジュアル・レイアウトのみを対象とし、バックエンド機能の実装可否はここでは扱いません。

変更点の要約:
- **削除**: Priority（優先度）列、Pause/Resume Queue、Pri Up/Down、Slotの複数枠前提、Knowledgeタブ（Obsidian連携）——いずれも現在バックエンドに存在しない（Backlog扱い）機能のため、実在しないボタン/データをデザインしない
- **修正**: System Health Barの「Queue: N items pending」→「Lock: Free / In-use (owner)」（実際の`doctor`が返す情報に合わせる）
- **維持**: トーン＆マナー、フォームファクター（トレイ常駐・Pin・コンパクトモード）、Statusの考え方（架空の%バーを出さない）、グリッド/詳細ペインの基本構造
- **将来拡張への配慮**: Priority/Slot/Knowledgeを後から追加してもレイアウトが破綻しないよう、拡張余地（予約列・予約タブ枠）だけデザイン上に残す。ただし今回は機能させない

## 1. プロダクト概要と目的
本アプリケーションは、ローカル環境で ChatGPT Web を自動操作する CLI ツール（`chatgpt-web-bridge`）を監視・制御するための**タスクトレイ常駐型・軽量管制塔 GUI** である。
複数の AI エージェント（Claude Code, Codex, Antigravity）および人間が、単一のブラウザ・プロファイル・ログインセッションを共有して利用するため、**「今、誰が、どのリソースを使って何を処理しているか」を一目で把握できる高い情報密度と静かな機能美**が求められる。

現バックエンドは**実質シングルスロット**（同時に1リクエストのみ実行可能、ロックで排他）。GUIはこの制約を隠さず、正直に表現する。

## 2. デザインコンセプトとビジュアルトーン
### 2.1 トーン＆マナー
- **キーワード**: 静かな計器（Quiet Instrument）、ミニマル、機能美、タイポグラフィ重視。
- **過剰な装飾の排除**: 絵文字、過度なグラデーション、派手なネオン発光（サイバーパンク感）は一切使用しない。
- **色彩設計**:
  - ベース背景: チャコールグレー〜ダークスレート（`#121417`, `#1a1d21`）
  - サーフェス/ボーダー: 落ち着いたダークトーン境界線（`#2a2e33`, 1px solid）
  - テキスト: 高コントラストを避け、目に優しい白〜グレー（プライマリ `#e1e4e8`、セカンダリ `#8b949e`）
  - 状態アクセント（アクセントは情報表示にのみ限定使用）:
    - 正常・稼働中（Active / Running）: 控えめで上品なミントグリーン / セージグリーン（`#2ea043` または `#10b981`）
    - 待機（Waiting for lock）: ニュートラルブルーまたはスレート（`#388bfd` / `#6e7681`）
    - 警告・要確認（Warning / CAPTCHA）: アンバーイエロー（`#d29922`）
    - エラー・中断（Error / Stopped）: 落ち着いたクリムゾンレッド（`#f85149`）

## 3. フォームファクターとウィンドウ挙動
1. **トレイ常駐 & クイックポップアップ**:
   - 普段はタスクトレイ（通知領域）に格納。
   - グローバルホットキー（例: `Win + Shift + C`）またはトレイアイコンクリックで、画面右下（または前回の表示位置）に瞬時にスライドイン/フェードイン表示。
2. **最前面ピン留め（Always on Top）**:
   - ウィンドウヘッダーの「Pin」トグルにより、他の作業ウィンドウ（IDEやブラウザ）の最前面に固定可能。
3. **レスポンシブ・リサイズ（2つの表示モード）**:
   - **標準モード（Default View）**: タスク一覧（グリッド）＋下部詳細ペインを表示するフルビュー。
   - **コンパクトモード（Mini Monitor View）**: ウィンドウを極小サイズまで縮小した際、ヘッダーと現在実行中ジョブの1行（ステータス＋インジケータ）のみに切り替わり、画面隅に置く監視計器として機能。
4. **アプリ内オーバーレイ通知**:
   - OS標準トーストは使わず、ウィンドウ内（またはトレイ近傍）に数秒で上品にフェードアウトするカスタム通知を表示。
   - ヘッダーに通知の即時ON/OFF（Mute）トグルスイッチを常設。

## 4. 画面レイアウト構成（μTorrentライクな情報設計）
画面は大きく「ヘッダー/ツールバー」「メインタスクグリッド」「詳細情報ペイン」の3層構造とする。
```text
+-------------------------------------------------------------------------------+
| Header & System Health Bar                                  [Pin] [Mute] [-] [x]
+-------------------------------------------------------------------------------+
| Action Toolbar (New, Stop, Refresh Cookie, Settings)                          |
+-------------------------------------------------------------------------------+
| Main Task Grid (Sortable Table)                                               |
| Caller  | Project | Title / Prompt Summary | Status    | Elapsed |[reserved]  |
|---------+---------+------------------------+-----------+---------+------------|
| Claude  | Auth    | Token refresh review   | Generating| 01:24   |            |
| Human   | Core    | DB Index Optimization  | Waiting   | --:--   |            |
| Codex   | Refact  | Type definition batch  | Waiting   | --:--   |            |
| Claude  | API     | Route handler security | Completed | 00:45   |            |
+-------------------------------------------------------------------------------+
| Detail Pane (Tabs: Overview | Prompt | Response | Logs  [+ reserved tab slot])|
|                                                                               |
| [Selected Task Markdown Content / Metadata View]                              |
|                                                                               |
| Action Buttons: [Copy Markdown] [Open in Browser]                            |
+-------------------------------------------------------------------------------+
```
`[reserved]` 列と `[+ reserved tab slot]` は、将来Priority/Slot/Knowledge機能を追加する際の受け皿としてレイアウト上の余白だけ確保する。今回は非表示または空欄でよい（ダミーの数値やボタンを描画しない）。

## 5. 各コンポーネントの詳細要件
### 5.1 ヘッダー & システムヘルス（System Health Bar）
表示項目:
- アプリケーション識別子（例: `BRIDGE // CONTROL`）
- システム稼働ステータス（小さなインジケータドット）:
  - `Bridge`: Ready / Busy / Offline
  - `Chrome`: Connected / Disconnected
  - `Auth`: Valid / Expired
  - `Lock`: Free / In-use（誰が使用中かを表示。実際の`doctor`コマンドが返すロック所有者情報に対応）
- 右端ユーティリティ: `[Always on Top]`, `[Notifications: On/Mute]`, `[Minimize]`, `[Close]`

### 5.2 アクションツールバー
既存CLI/daemonコマンドをそのまま呼び出すだけの、実在する操作のみ:
- `New`: 手動プロンプト投入モーダルを開く（送信時にロックが使用中なら、待機表示のみでキュー投入はしない — 現状バックエンドに待ち行列機構はない）
- `Stop`: 選択中タスクの中断シグナル送信
- `Refresh Cookie`: 再ログイン導線（ブラウザを手動ログイン用に開く）
- `Settings`: 各種パス設定、ショートカット設定

### 5.3 メイングリッド（タスク一覧テーブル）
列構成:
- `Caller`（発注元）: Claude, Codex, Antigravity, Human などのバッジ表示
- `Project`（プロジェクト）: ChatGPT側のProjectフォルダ名
- `Title`（タイトル）: リクエストの要約（`meta.json`由来、またはプロンプト冒頭）
- `Status`（状態）:
  - `Waiting`（ロック解放待ち。スケジューラによる優先度制御ではない、単純な排他待ち）
  - `Submitting`（ブラウザ投入中）
  - `Generating`（回答生成中・不確定インジケータ稼働）
  - `Collecting`（回答回収中）
  - `Completed`（完了）
  - `Stopped`（ユーザー中断）
  - `Failed`（失敗）
  - `Blocked`（CAPTCHA / 認証切れ等で人間介入待ち）
- `Elapsed`（経過時間）: ※事前トークン数が不明なため、架空の%バーは出さない。生成中は「流れるような不確定プログレス（Indeterminate Line）」＋実測経過時間（例: `01:24`）を表示

インタラクション:
- 行クリックで下部ペインに該当タスクの詳細を展開
- 行の右クリックコンテキストメニュー:
  - 回答を回収 (Collect)（送信済み・未回収の失敗時のみ活性化。既存`collect`コマンドに対応）
  - 新規IDで再実行（送信前エラーまたは完了タスクのみ）
  - タスクを中断 (Stop)
  - requestIdをコピー

### 5.4 下部詳細ペイン（タブ切り替え）
- **タブ1: Overview（概要）**
  - Request ID（クリックでコピー）
  - ChatGPT URL（クリックで外部ブラウザ＝普段のプロファイルで会話を直接開く）
  - Preset / Model（Instant / Medium / High / Pro、モデル名）
  - Repo / Session（発注元のローカルリポジトリパスとセッション識別子）
- **タブ2: Prompt（プロンプト）**
  - 投入されたプロンプト本文（Markdownプレビュー / Rawテキスト切り替え）
  - 添付ファイル一覧（チップ表示）
- **タブ3: Response（回答）**
  - 取得した回答Markdownのシンタックスハイライト付きレンダリング
  - 右上に `[Copy Markdown]` ボタン
- **タブ4: Logs（観測ログ）**
  - 該当リクエストのライフサイクルログ（受付 → ロック取得 → 送信 → 完了観測）
  - デバッグ用の詳細ログと通常ログのフィルター切り替え
- **（予約枠）タブ5**: 将来のナレッジ連携等のための空きタブ位置。今回はタブバーに追加ボタンや空タブを描画しない。デザイン上、タブが5個目以降に増えても崩れないタブバー設計になっていることだけ確認する

## 6. デザイン提案依頼事項
上記仕様を踏まえ、以下の複数パターンのUIデザイン案（レイアウト構成およびスタイリング）を提案してください。実装はCodexが別途行うため、**構造とスタイリング方針が明確に読み取れること**を優先してください。

### 案A: クラシック・インスツルメント型（μTorrent正統進化版）
上下均等分割、データグリッドを主役とし、情報密度の最大化を図った実用志向のレイアウト。

### 案B: モダン・スプリットパネル型（モダンIDE / Slack風）
左側にスリムなキュー/履歴リスト、右側に大きく詳細・Markdownプレビューを配置した左右2カラム構造。

### 案C: ミニマル・フローティングバー型（コンパクト監視特化）
普段は極小のフローティングバーまたはトレイポップアップとして振る舞い、必要な情報だけを階層的に展開する省スペース設計。

各案について、以下を明記してください:
1. 画面レイアウトのアスキーアート（または構造図）
2. Tailwind CSSクラスを用いた主要コンポーネントのスタイリング方針
3. 上記「4. 画面レイアウト構成」の`[reserved]`列・予約タブ枠を、その案のレイアウトでどう扱うか（非表示か、空白領域として確保するか）
