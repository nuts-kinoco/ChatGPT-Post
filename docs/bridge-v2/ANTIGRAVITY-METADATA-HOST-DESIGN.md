# Antigravity metadata host wiring

This is a follow-on to reviewed PR10 (b9be3404), using the existing isolated metadata probe and provider catalog view. It enables no inference, execution grant, account sign-in, inherited credentials, model aliases or new model grammar.

## Entry point and UI

A production UI host may receive an explicit trusted Antigravity metadata configuration, either through its trusted deployment or a strictly parsed local configuration path supplied to `chatgpt-bridge ui --antigravity-metadata <path>`. The configuration contains only the registered executable path, expected binary SHA-256, owner UID, context ID, and explicit enabled/background-refresh booleans. There are no argv, env, prompt, credential, account or callback fields. It never comes from HTTP. Disabled and demo hosts spawn nothing.

The UI server constructs and starts the concrete metadata host after binding its loopback capability server. Startup checks the cache, then runs bounded version/help/models only when needed. Version/help use existing inspectInstalledAntigravity; models uses AntigravityCatalogSource. The existing private empty HOME/cwd and fixed minimal env remain, so authentication and availability in an ordinary installed user account are not inferred. Windows remains unavailable for this Linux-only probe.

GET /api/provider-catalog reads the cached view only. POST /api/provider-catalog/refresh accepts only a fixed empty versioned body; it may request a metadata refresh subject to ownership, auth latch and cooldown. Repeated clicks coalesce. Ordinary page reload/read never triggers a probe. A small catalog panel displays provider, observed date/source, stale/unknown state and precise blocked reason, with a metadata refresh button; it does not affect task/composer model selection. Both public view and panel explicitly label the private empty-HOME metadata context and retain accountAvailability: unknown. Auth-required wording means this isolated probe could not list models; it makes no claim that the ordinary AGY account is signed out and provides no login/context-switch action. The existing token, origin, host and request-body guards apply.

## Durable lifecycle

Use a private host-local SQLite store with bounded strict JSON records, transactional saves, scope binding and integrity hash (corruption detection, not signer identity). Its one fixed production path is stateDir/antigravity-metadata/production/catalog.db, with no cache path field in config or HTTP. Owner and record bind the complete provider/route/context/binary scope plus the canonical trusted-config SHA-256 revision. A conflicting configuration is blocked at the existing owner/store, never redirected to a different database. Reject symlink/hardlink/untrusted path ownership/modes. The host and same-user local code remain trusted; this is not OS confinement.

Acquire one persistent owner marker transactionally before any probe. A second host and a host restarted after crash refuse all probes while that marker remains. No PID guessing, automatic stale-lock deletion or alternate state directory is used to regain availability. Graceful close clears the marker only after all owned metadata processes have actually exited and the last state is durable; an unresolved process keeps the marker and close reports pending. A trusted operator may repair an interrupted registration only after establishing its old process is stopped; no HTTP reset is added.

The durable host record includes the verified version/help capability observation (version, help SHA and capabilities), bound to the exact registered binary SHA and isolated context, alongside the cache checkpoint. It is validated before constructing AntigravityCatalogSource on warm restart. The record also includes the whole discovery attempt time, next allowed time and inspection failure/auth state; these are saved before any version/help/models stage, including first installation inspection. An inspect error consumes the attempt cooldown, and inspect auth errors latch exactly like models auth errors. A warm valid checkpoint does not rerun version/help.

The cache checkpoint includes the verified snapshot, scope, last attempt, next allowed attempt, failure/error state and last clock. Hydration validates bounds and exact scope; corrupt/future/inconsistent state remains blocked and is not replaced with an empty cache. A synchronous persistence hook runs on cache transitions, including before source.start. Failed persistence blocks probe start/retry. On timeout, ownership remains until exit; late results never replace the timeout. Checkpoint callbacks after actual exit persist the retained failure state.

The host uses a lease-owning wrapper around AntigravityMetadataProbe for every operation. It records each lease before awaiting a result and retains it until exited resolves; an exit rejection remains unknown. Existing inspectInstalledAntigravity must accept that structural start port (or an equivalent tracked inspection helper), so it cannot hide version/help ownership from the host. beginShutdown synchronously fences new stages, refresh buttons and timers before requesting cancellation of every owned lease. close waits a bounded interval for both the discovery future and every exited lease. A timeout/rejection reports shutdown pending and keeps the same owner marker/store open; an explicit close retry joins those same leases without starting any new work. Only known drain plus successful final persistence allows marker release and store closure. Bind failure closes an unstarted host with zero probe calls.

Auth-required is latched durably: no startup, timer or button repeats a prompt in the same context. This isolated metadata context cannot gain auth through the UI. A context change requires explicit trusted configuration and a separately reviewed operational registration; it is not inferred from a retry. Inspect failures similarly retain precise failure and cooldown without leaking output. Configuration paths, raw output and secrets are not returned by UI.

Default metadata interval and TTL are 24 hours to minimize metadata traffic while text format remains unverified. Background refresh is explicit opt-in and exists only while the host runs. A warm fresh cache requires no metadata process. No absolute zero-quota claim is made. Metadata-only calls remain distinct from model requests.

## Acceptance

Fake-process/store/server/UI tests cover disabled/demo/no config, first startup version/help/models, warm restart with no process, expiry once, coalesced explicit refresh, durable auth latch, corrupt/wrong-context/future storage, concurrent owners, crash marker, timeout then late success/no overlap, persistence failure before spawn, graceful/pending close, GET-only no probe, fixed-body POST, token/origin rejection and text-only label rendering. Existing provider schemas, app behavior and all regression suites remain unchanged.
