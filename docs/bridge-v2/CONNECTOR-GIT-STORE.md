# Host-mediated Git storage

`GitHubConnectorStore` runs the same immutable Git Database algorithm as the REST
store through an already-authorized connected GitHub host. The host callback must
relay authentic tool results. It never accepts model-written operations, reads
credentials, sets up authentication, or falls back to HTTP. This is a mediated
runtime boundary; it does not prove standalone unattended GitHub connectivity.

The fixed repository/branch and namespace constrain all reads and mutations. Writes
are bounded append-only batches, never forced updates or deletion. The adapter
checks exact commit/tree/blob response identities, downloaded blob hashes and sizes,
complete bounded recursive tree metadata, regular-file mode, path collisions,
created-tree overlay preserving every unrelated leaf/type/mode/SHA, created commit's
sole parent and tree, and visible desired content before reporting success. It does
not reconstruct the cryptographic hash of every commit/tree object: the authenticated
host/connector and GitHub service are trusted to relay their object metadata.

Unrelated repository dotfiles, Unicode names, executable files, symlinks and submodules
remain untouched and no longer prevent a snapshot. They cannot become artifact targets
or occupied ancestors. Truncation, missing/wrong identities, malformed metadata and
ambiguous publication fail closed. Lost update replies reconcile existing content;
a failed/unknown operation never reruns a model or silently retries a mutation.

The callback operation vocabulary is limited to fetch, create_blob, create_tree,
create_commit and non-force update_ref. Its exact arguments are generated by Bridge.
A host-mediated synthetic trial still needs separately approved request actors/signing,
registry, destination, durable requester pin and the provider execution prerequisites.
No live Git exchange is claimed by the unit tests.
